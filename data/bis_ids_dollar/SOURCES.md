## BIS terms

The BIS terms of use are at https://data.bis.org/help/legal (read by hand on 23 Oct 2026). The core condition is: "The use of the statistics is unrestricted, provided that" the BIS is cited as the source when the statistics are reproduced. In plain words, the other conditions are: a translation must say it is not an official BIS translation; use must not mislead or imply endorsement or affiliation; a commercial product may not charge extra for including them; the BIS gives no warranty and accepts no liability; nothing in the statistics is investment advice; no other use is permitted. The terms for the API are separate and concern the API itself, which is not redistributed. No copy of the terms is committed.

## Release dates

Release dates are the "International debt securities" line (category IDS) of the BIS release calendar (https://data.bis.org/release-calendar; the rows load from the calendar's JSON feed), never the "Debt securities statistics" (DSS) rows, which carry a different quarter on the same dates. The script holds 15 release dates (2023-Q1 to 2026-Q3, as constants); only the latest ones reach the outputs, through the ids_release column, which is the latest date on or before the pull date. The most recent five: 2025-Q3 on 2025-12-08, 2025-Q4 on 2026-03-16, 2026-Q1 on 2026-06-15, 2026-Q2 on 2026-09-14, 2026-Q3 on 2026-12-07. Locational banking statistics: 2026-Q2 on 2026-10-30. "Data are released no later than the specified date."

## The 3P finding

In this dataflow the residence code `3P` is labelled "All countries excluding residents" but is the world total including US residents: at 2019-Q4 (all issuers, outstanding) 3P equals 5R + 4T + 1C exactly, and 3P minus the sum of the 131 leaf residence codes (every code except 3P, 5R, 4T, 3C, 4Y, 4W, 4U; `1C` and `1Z` are leaves) is +57. An alphabetic leaf rule (two letters only) would drop 1C and 1Z and leave a gap of +899,535. So NON_US = ALL - US. Check C04 guards this each build.

## Window reasoning

The paper states a five-year increase and gives its data date as Q4 2019 (page 4: international debt securities plus cross-border loans "$22.6 trillion as of Q4 2019"). It does not print the start quarter. The window is read as the five years to that date, 2014-Q4 to 2019-Q4 (twenty quarters, level to level); a window one quarter earlier (2014-Q3 to 2019-Q3) is printed beside it as P4 without a reading. The paper's Graph 10 definition (loans by banks in all reporting countries including interoffice loans, and debt securities including issuance by entities in the United States) is P1; Graph 1's note 3 (excluding interoffice claims) is P3. The definition check: IDS ALL at 2019-Q4 plus the all-sector US-dollar cross-border loans is close to the paper's $22.6 trillion (check C11).

## Column provenance

`outstanding_usd_m` and `net_issues_usd_m` are BIS series (measures I and G) for immediate-issuer sector, issuer residence, all currencies-USD, international markets, face value; `change_in_outstanding_usd_m` and `other_change_usd_m` are differences computed here; NON_US is ALL minus US computed here; US_NATIONALITY is the BIS nationality series with residence 3P and nationality US. LBS values are the BIS series S (stock) and F (FX and break adjusted change), counterparty-country 5J and US, counterparty sectors A and I.

## Build decisions

1. **R3-1 reading rule (post-registration fix 1, 23 Oct 2026; disclosed in the spec before this script ran).** Old rule (round 1): the verdict rested on P1 alone, band 65-85%. New rule (R3-1): `consistent` only if P1 and P2 both lie inside 65-85%, `mixed` if they fall on opposite sides, `not_consistent` if both fall outside, `undefined` if either is blank. The values seen when the rule changed: P1 75.56%, P2 91.78% (both reviewers had computed them; this script had not run). The old rule would have printed `consistent` on the 23 Oct 2026 vintage; the new rule can only withhold that reading, never create it. The window (2014-Q4 to 2019-Q4) and the band were not changed. Old output values: reading `consistent` on the P1 row; new output values: `mixed` on both rows.
2. **Round 4 outranks the body (O-11, O-12, O-13, O-14).** README sentence 1 is the second reviewer's ("This folder shows how many US dollars ..."), not section 5.1's draft; the R2-2 sentence is round 4's full text with its two numbers generated; the C04 signed test is round 4's (PASS if |3P - sum of leaves| <= 0.1% of 3P and |(3P - sum of leaves) + US| >= 0.9 x US; FAIL and write STOP only if the second leg fails) and not section 8's earlier "d < 0 and |d + US| <= 10% of US"; the BIS terms are linked, quoted in under 15 words and summarised (O-14), so section 2.5's "full text" and section 5's "SOURCES.md carries the full text" are not followed and no copy of the terms is committed.
3. **R2-2 sentence when the other shares are not all outside the band.** Round 4 prints it whenever P1 is inside the band and says the other shares are "outside the band". The numbers are generated; if a later vintage puts one of P2, P3 or P4 inside the band the clause becomes "and at least one of these lies inside the band" so the sentence stays true. On this vintage it is the reviewer's text.
4. **Disclosure note on the P1 row.** The spec's text ends "would read consistent". The last word is generated from the round-1 rule applied to the current P1 share (consistent inside the band, not_consistent outside), so the note stays true on a later vintage. On the 23 Oct 2026 vintage it is the spec's text.
5. **C05 covers both measures.** The identities are checked for outstanding and for net issues, for ALL, US, ADV, EMDE and INTL_ORG (ALL = GOV + FIN + NFC + INTL_INST; FIN = its five parts) and, at sector ALL, ALL = ADV + EMDE + INTL_ORG; one row per quarter from 2013-Q4, status the worst of the identities. The spec does not name the measure; the stricter reading was taken.
6. **C05b is evaluated per measure (supervisor ruling after the first real-data build).** The US-only identities (US ALL = GOV + FIN + NFC; US FIN = its published parts; each within 5) are tested for outstanding and for net issues separately, and the verdict of a measure decides the NON_US cells of FIN_CENTRAL_BANK and INTL_INST for that measure only. If the identities hold, the cell takes the US value as zero (`us_series_absent`). If a US value the test needs is absent, the cell is blank with `us_value_absent`; if the values are present but the gap exceeds 5, it is blank with `us_sum_mismatch`. The one C05b row per quarter in checks.csv reports both measures and is a WARN if either fails. Old rule (first build): one joint verdict for both measures, so a missing US net-issue value in 2026-Q2 also blanked the outstanding cells as `us_sum_mismatch`; the 2026-Q2 outstanding gaps are -1 and 0, so under the new rule those cells are filled. Real data had been seen. Status `us_value_absent` is an addition to the spec's list of statuses.
7. **NON_US status of a row** combines its two measures: both absent -> absent; any us_sum_mismatch -> us_sum_mismatch; any us_value_absent -> us_value_absent; any partial, or one measure absent -> partial; any us_series_absent -> us_series_absent; else ok. A source row is ok when both measures are present, absent when both are missing, partial otherwise.
8. **Added check rows.** C04b (2019-Q4 d = +57 over 131 leaves), C04c (ADV + EMDE + INTL_ORG = ALL at 2019-Q4), C06b (2019-Q4 sign pins), C15 (descriptive labels), C16 (pull order), C17 (the release line of the calendar is the release of the pull's latest quarter, which would differ if the DSS rows were read), C18 (folder guards on the rendering), C19 (no raw SDMX file anywhere in the repository outside the cache; the files git would commit are scanned) and C13 (a second build leaves every sha256 unchanged). Pins are one-vintage checks: IDS pins FAIL while 2026-Q2 is the latest quarter and WARN once a later quarter is in the file; C10, C11 and C14 FAIL on a pull dated before 2026-10-30 and WARN after (2.4).
9. **Scoring uses the first qualifying pull.** The baseline is the earliest pull whose IDS release is 2026-09-14; the score uses the earliest later pull whose latest quarter is 2026-Q3 or later (section 7 says "newest", the CALENDAR text says "the first pull whose latest quarter is 2026-Q3"; they agree until a second pull holds 2026-Q3, and the first is the one the statement names). A cell absent in either pull makes the result VOID. The change is compared unrounded: the registered 1.0% is exceeded when the exact change is above 1.0.
10. **Revisions.** Cells are the quarterly.csv cells (all groups including NON_US, both measures, from 2014-Q3), compared between the newest pull and the newest earlier one for the quarters the earlier pull holds; a change from or to blank counts as a change. `value_*`, `change_usd_m` and `change_pct` are blank where a side is blank. The first pull writes one `baseline` row (`vintage_prev` = baseline).
11. **cgfs_check.csv details.** `lbs_break_quarters` counts quarters after `first_quarter` up to `last_quarter` in which any stock series used is flagged B (P3: all-sector or related-offices; N1: all-countries or United States). P2's loan figure is the flow sum and its break sum is the all-sector stock change over the same window minus that sum, as in the spec's C14 table. LBS-derived values keep the published three decimals (the break sum is 656,777.368, not 656,777). `denominator` is the text of the sum of the two increases.
12. **Windows.** `quarters_blank` counts quarters in which net issues, change or other change is blank; each sum is blank when its own series has a blank quarter. `first_quarter` and `last_quarter` are the first and last quarter of the window. The group denominator text carries the ALL-sector sum.
13. **Summary statistics.** Minimum and maximum take the earliest quarter on a tie; Q1 and Q4 minimum and maximum run over 2019-Q1 to the latest quarter; Q6 summarises every comparison in revisions.csv. `blind` follows section 4 literally (ALL, US, NON_US only, plus US_NATIONALITY, and every Q5 row `no`); rows for ADV, EMDE and INTL_ORG are `yes` unless they are Q5.
14. **Request log and dates.** `fetch` names the pull folder from the UTC date of the clock, which is the one place a clock is read; every date in an output comes from a pull-folder name (R5). Each pull folder keeps its own fetch_log.csv; the committed fetch_log.csv is rebuilt from all of them. The seeded replies the spec author cached were not used. The 2026-10-23 pull took seven requests across two runs: the first sent F1 (200) and F2, which timed out after 120 s (a socket fault, no reply, no STOP); the supervisor then resumed the fetch, which skipped the saved F1 and sent F2 to F6 (all 200). F2 was therefore requested twice and every other file once; the log shows all seven rows.
15. **A timeout is not a refusal.** The spec latches STOP on a status other than 200 or a body that fails a content test. A request that gets no reply (a socket timeout or reset) has neither: the invocation ends, the request is logged with status socket_fault, no STOP file is written, nothing is retried by the script, and the files already saved stay in the pull folder. Whether to resume (a further fetch skips the saved files and sends only the requests still missing) is left to a person.
16. **Failed builds.** A build with any FAIL row writes its files to data/bis_ids_dollar/_FAILED/ (gitignored) and leaves the committed files alone, as the earlier builds do.
17. **LBS dataflow name.** The spec fixes the IDS dataflow name; for the LBS dataflow the observed name "Locational banking" is tested as a soft label (WARN) while its id, structure and dimension order are hard.
18. **Wording.** No generated file labels P1 to P4 with the phrase that section 6.3 bans for them; the README says the paper's measure is global and that N1 is not the paper's measure. The causal pattern of section 6.3 is the guard, copied as a literal; the planted-phrase test covers each alternative. The literal's lean-clause (inherited from bin/hedged_ust_yield.py) matches the past tense but misses the bare present tense, so a second, stricter pattern covering the present and -ing forms is applied beside it; the literal is unchanged.
19. **Raw-file rule outside the folder.** Inside data/bis_ids_dollar/ a raw SDMX file is any file with a line beginning with the first two column names of an IDS or LBS CSV header (6.1), or whose body holds the structure-message key named in 6.1, whatever its name or first line; this file therefore never writes that key out. For the rest of the repository (C19, and the second look in bin/check.sh M20) the key half applies to JSON bodies only, because the script and the spec name that key in prose and would otherwise be reported; the line rule applies to every file git would commit.
